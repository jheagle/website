    Cloakfall

    Every fleet is cloaked. Fire blind into the dark. The last fleet still hidden wins.

    Cloakfall is a hidden-fleet grid game in a dark sector of space: 2 to 4 fleets, any mix of players and robots, in a free-for-all where the robots hunt each other too. Play it solo against robots, hot-seat on one screen, online with friends, or just watch the robots play. It is fully keyboard playable (Tab onto a board, arrow keys, Enter to fire) and screen-reader friendly: every cell is named by its coordinate and what it shows ("B4, miss").

    Play it at https://joshuaheagle.com/projects/cloakfall/play.html (docs: https://joshuaheagle.com/projects/cloakfall/docs/).

    Built with TypeScript on treeloom (the page as data) and treeloom-matrix (the grids), with a socket.io lobby server for online play.

    Formerly "Battleship": renamed in November 2026, since that name is Hasbro's trademark. The rules of the classic pencil-and-paper game are free to use; the name, and Hasbro's own rules text, are not.

    Icons

    icons/icon.svg is the source: a cloaked ship fading into the dark, its nose caught by a flare. The PNGs and favicon.ico (16, 32 and 48 px) in icons/ are rendered from it with sharp, the same way the website builds its own icons (scripts/build-icons.mjs there). Re-render them after changing the SVG.

    Running locally

    Solo, hot-seat and robots-only play are just the static page - nothing to run, open the built page (e.g. http://cloakfall.local) in a browser.

    Online Multiplayer additionally needs the lobby server running:

    npm run serve:lobby

    This compiles and starts server/lobbyServer.ts on port 3002 (src/network/lobbySocket.ts's own DEFAULT_URL). The page itself still needs to be served separately (same as local play) - this is just the socket.io server it talks to for room hosting/joining and the remote game itself.

    Checking full games in a browser

    Three scripts play a whole game in a real headless Chromium (Playwright) against the built page, and fail when the game doesn't reach its final score or a page has an error (uncaught errors, console errors, failed requests). Build first:

    npm run build
    npm run e2e:robots    # Robots only (~2 min)
    npm run e2e:hotseat   # local multiplayer, two players on one screen (~2 min)
    npm run e2e:online    # online: starts the lobby server, a host and a guest page (~1.5 min)
    npm run e2e           # all three

    Players shoot at random cells. Each turn waits for the game itself (a shot showing, whose turn the badge says) rather than fixed pauses, so the online game's two-part updates (the shot, then the turn change) don't trip it. npm run e2e:online also reports how much of the guest's page each shot changes (elements added, attribute writes), to compare rendering changes. E2E_LIMIT_MS changes how long a game may take; E2E_DEBUG=1 logs each online turn. The online check needs port 3002 free (no lobby server already running). They use js-build-tools' page tools (watchPage, clickLabel, trackMutations, serveStatic); a browser binary is needed once per machine: npx playwright install chromium.
