BrowserConfig

Configurations for building the browser files.

Type:
  • Object.<string, Setting>
Properties
NameTypeDescription
enabledBooleanSetting

'true' to generate browser bundled files; 'false' for node environment only

fromStringSetting

The search pattern used for retrieving compiled distribution files.

nameStringSetting

The name to use for the browser-bundled output file (.js will be appended).

toStringSetting

The output directory for browser-bundled files.

ignoreArrayableSetting

Module names or file paths which resolve to an empty object ({}) in the bundle instead of their real contents. For a dependency which is only reached because it is the default value of an option you always override (for example a selector engine's default DOM adapter, when you always pass your own), this keeps it (and anything only it requires) out of the bundle, as long as your code never actually reaches the real module by not overriding that option. See browserify's b.ignore(file).

excludeArrayableSetting

Module names or file paths left out of the bundle entirely; requiring one at runtime throws unless something else provides it (for example a script tag loading it separately). See browserify's b.exclude(file).

bundlesArray.<module:gulpConfig~AdditionalBundleConfig>

Additional bundles to produce alongside the primary one (name/dist.main/ignore/exclude above) - for example a render-only variant built from a different entry point than the full bundle. Empty by default: a project that never sets this gets exactly the one bundle it always did.

DocsConfig

Configurations for generating the HTML documentation of a project's own source, with either TypeDoc (real TypeScript types) or jsdoc (a modern theme over jsdoc's own classic default) - see docs.method.

Type:
  • Object.<string, Setting>
Properties
NameTypeDescription
enabledBooleanSetting

Toggle generating the documentation from the source. When it is on the build does this instead of generating the readme from the jsdoc comments of the compiled files.

fromArrayableSetting

The directory holding the source, each folder in it becomes a module (TypeDoc) or is scanned recursively (jsdoc). jsdoc also takes a list of directories and files.

inBuildBooleanSetting

Generate the documentation as part of build (the default). Turn it off to only generate it when you run the docs task yourself (gulp docs), for example when docs.to points into another repository and you only want to publish the documentation of a release.

indexStringSetting

The markdown file used as the front page of the documentation.

logLevelStringSetting

How much TypeDoc reports: Verbose, Info, Warn, Error or None. Not used by jsdoc.

methodFlagStringSetting

'typedoc' or 'jsdoc'. False (the default) infers it from typescript.enabled - 'typedoc' when on, 'jsdoc' when off - so an existing TypeScript project's config needs no change to keep working exactly as it already does; set this explicitly to override that inference either way.

themeStringSetting

The jsdoc theme package to use (only meaningful when method is 'jsdoc' - TypeDoc keeps its own default regardless). Defaults to 'clean-jsdoc-theme'.

titleStringSetting

The name of the documentation, defaults to the name in the package.json.

toStringSetting

The directory to generate the documentation in (it is cleared first).

tsconfigFlagStringSetting

The tsconfig file to read the source with (TypeDoc only), defaults to the one of typescript.config.

LintConfig

Configurations for linting (see module:partials.neostandardLint).

Type:
  • Object.<string, Setting>
Properties
NameTypeDescription
rulesObject.<string, *>

ESLint rule overrides layered on top of neostandard's own config, scoped to the same files neostandard itself lints. For a rule that is wrong for your project specifically (for example a test fixture that deliberately contains text neostandard mistakes for a real syntax problem), rather than something to fix in your code. Empty by default: a project that never sets this gets exactly neostandard's own rules, unchanged. Keyed and valued exactly as ESLint's own rules object - see https://eslint.org/docs/latest/use/configure/rules.
