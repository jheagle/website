BrowserConfig: Object.<string, Setting>

gulp.config.mjs:81

Configurations for building the browser files.

Properties

  • enabled (BooleanSetting) — 'true' to generate browser bundled files; 'false' for node environment only
  • from (StringSetting) — The search pattern used for retrieving compiled distribution files.
  • name (StringSetting) — The name to use for the browser-bundled output file (.js will be appended).
  • to (StringSetting) — The output directory for browser-bundled files.
  • ignore (ArrayableSetting) — Module names or file paths which resolve to an empty object ({}) in the bundle instead of their real contents. For a dependency which is only reached because it is the default value of an option you always override (for example a selector engine's default DOM adapter, when you always pass your own), this keeps it (and anything only it requires) out of the bundle, as long as your code never actually reaches the real module by not overriding that option. See browserify's b.ignore(file).
  • exclude (ArrayableSetting) — Module names or file paths left out of the bundle entirely; requiring one at runtime throws unless something else provides it (for example a script tag loading it separately). See browserify's b.exclude(file).
  • bundles (Array.<module:gulpConfig~AdditionalBundleConfig>) — Additional bundles to produce alongside the primary one (name/dist.main/ignore/exclude above) - for example a render-only variant built from a different entry point than the full bundle. Empty by default: a project that never sets this gets exactly the one bundle it always did.

AdditionalBundleConfig: Object.<string, Setting>

gulp.config.mjs:91

One additional bundle - everything but name falls back to the primary bundle's own value when omitted, so an additional bundle only has to specify what's actually different about it.

Properties

  • name (StringSetting) — The name for this bundle's output file and standalone export - must be unique among all of a project's bundles.
  • main (StringSetting, optional) — This bundle's own entry point. Falls back to dist.main when omitted.
  • ignore (ArrayableSetting, optional) — This bundle's own ignore list. Falls back to browser.ignore when omitted.
  • exclude (ArrayableSetting, optional) — This bundle's own exclude list. Falls back to browser.exclude when omitted.

LintConfig: Object.<string, Setting>

gulp.config.mjs:125

Configurations for linting (see module:partials.neostandardLint).

Properties

  • rules (Object.<string, *>) — ESLint rule overrides layered on top of neostandard's own config, scoped to the same files neostandard itself lints. For a rule that is wrong for your project specifically (for example a test fixture that deliberately contains text neostandard mistakes for a real syntax problem), rather than something to fix in your code. Empty by default: a project that never sets this gets exactly neostandard's own rules, unchanged. Keyed and valued exactly as ESLint's own rules object - see https://eslint.org/docs/latest/use/configure/rules.

DocsConfig: Object.<string, Setting>

gulp.config.mjs:167

Configurations for generating the HTML documentation of a project's own source, with either TypeDoc (real TypeScript types) or jsdoc (a modern theme over jsdoc's own classic default) - see docs.method.

Properties

  • basePath (FlagStringSetting) — The path the documentation is served from, such as '/projects/my-lib/docs/' (jsdoc with clean-jsdoc-theme 5.x only). The theme's links start at the site root, so documentation served below it needs this. False (the default) serves it from the site root.
  • enabled (BooleanSetting) — Toggle generating the documentation from the source. When it is on the build does this instead of generating the readme from the jsdoc comments of the compiled files.
  • from (ArrayableSetting) — The directory holding the source, each folder in it becomes a module (TypeDoc) or is scanned recursively (jsdoc). jsdoc also takes a list of directories and files.
  • gitRevision (FlagStringSetting) — The git revision TypeDoc's "Defined in" source links point to (TypeDoc only). False (the default) is TypeDoc's own: the current commit, which changes every page on every commit. A branch name such as 'main' keeps the pages unchanged until the documentation itself changes; '{branch}' is the branch being built.
  • inBuild (BooleanSetting) — Generate the documentation as part of build (the default). Turn it off to only generate it when you run the docs task yourself (gulp docs), for example when docs.to points into another repository and you only want to publish the documentation of a release.
  • index (StringSetting) — The markdown file used as the front page of the documentation.
  • logLevel (StringSetting) — How much TypeDoc reports: Verbose, Info, Warn, Error or None. Not used by jsdoc.
  • method (FlagStringSetting) — 'typedoc' or 'jsdoc'. False (the default) infers it from typescript.enabled - 'typedoc' when on, 'jsdoc' when off - so an existing TypeScript project's config needs no change to keep working exactly as it already does; set this explicitly to override that inference either way.
  • theme (StringSetting) — The jsdoc theme package to use (only meaningful when method is 'jsdoc' - TypeDoc keeps its own default regardless). Defaults to 'clean-jsdoc-theme'.
  • title (StringSetting) — The name of the documentation, defaults to the name in the package.json.
  • to (StringSetting) — The directory to generate the documentation in (it is cleared first).
  • tsconfig (FlagStringSetting) — The tsconfig file to read the source with (TypeDoc only), defaults to the one of typescript.config.

Configurations: Object.<string, Setting>

gulp.config.mjs:211

A set of Configurations options defined by Settings.

Properties

  • browser (BrowserConfig) — Browser bundling configuration group.
  • cleanPaths (ArrayableSetting) — The paths for directories to delete before build.
  • copyFiles (Array.<CopyFilesEntry>) — Files to copy elsewhere, run via the copyFiles task - never automatically as part of build, since what this copies is often the live, publicly-reachable version of something (e.g. a bundle), and publishing it should be a deliberate step.
  • dist (DistConfig) — Distribution file generation configuration group.
  • docs (DocsConfig) — Generate the documentation of a TypeScript project configuration group.
  • fonts (FontConfig) — Fonts copy configuration group.
  • images (ImageConfig) — Minify and copy the images configuration.
  • lint (LintConfig) — Linting configuration group.
  • readme (ReadmeConfig) — Build readme files configuration.
  • rootPath (StringSetting) — Base directory of the project.
  • sass (SassConfig) — Compile CSS from SASS configuration.
  • srcPath (StringSetting) — The directory where your source files are stored (the files you manually created).
  • test (TestConfig) — Run test suite configuration.
  • typescript (TsConfig) — Compile from typescript configuration.
